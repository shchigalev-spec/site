# SIGNAL / TECH — Motion Storyboard

Этот документ задаёт смысл, состояния и поведение motion-системы. Конкретная библиотека вторична: анимация принимается только тогда, когда объясняет источник, путь, измерение, конструкцию или результат.

## 1. Грамматика движения

Каждая значимая сцена использует цепочку:

> симптом → неопределённость → измерение → выделение маршрута → решение → снижение энергии

Четыре типа движения:

1. **Импульс** — короткий, асимметричный, с быстрым фронтом и длинным затуханием. Показывает источник.
2. **Распространение** — движется по геометрии помещения и меняет направление на примыканиях. Показывает путь.
3. **Сканирование** — один управляемый проход, связанный с прогрессом пользователя. Показывает измерение; не зацикливается.
4. **Сборка** — слои расходятся, фиксируются и возвращаются. Показывает конструкцию.

Нельзя обозначать шум случайным облаком частиц. Частицы допустимы только как вторичный след вокруг вычисляемой траектории и должны затухать по мере диагноза.

## 2. Motion-токены

| Токен | Значение | Применение |
|---|---:|---|
| `--motion-micro` | `140ms` | press, focus, marker |
| `--motion-ui` | `260ms` | контролы, панели, подписи |
| `--motion-state` | `520ms` | смена выбранного профиля |
| `--motion-scene` | `900ms` | несвязанная со скроллом смена сцены |
| `--ease-enter` | `cubic-bezier(.16,1,.3,1)` | появление управляемого слоя |
| `--ease-exit` | `cubic-bezier(.7,0,.84,0)` | уход энергии |
| `--ease-physical` | `cubic-bezier(.22,.72,.2,1)` | конструктивные слои |

Scroll-driven timelines линейно связаны с прогрессом; easing используется внутри отдельных морфов, но не должен создавать ощущение scroll hijacking. Никакого инерционного перехвата колеса.

## 3. Hero acoustic scan — pinned 220vh

### 3.1. Слои сцены

Один sticky viewport содержит:

- cinematic room plate;
- depth map / несколько планов для лёгкого perspective parallax;
- слой поверхностей: потолок, стены, пол, вентиляция, розетки, примыкания;
- acoustic field: Canvas или лёгкий shader с маской маршрута;
- scan plane;
- route lines;
- exploded construction layers;
- текстовый слой и CTA в обычном DOM;
- постоянный индикатор `01 / СИМПТОМ` → `04 / РЕШЕНИЕ`.

Текст размещён по краям архитектуры и не перекрывает смысловой центр комнаты. Desktop допускает движение камеры не более 6–8% по глубине. Mobile использует подготовленные планы и 2.5D masks вместо тяжёлого WebGL.

### 3.2. Таймлайн

#### 0–24% — Состояние 1. Симптом

- тёплый жилой интерьер виден целиком;
- от неопределённой области за пределами кадра входят 2–3 разреженных импульса;
- импульсы частично отражаются от стен, но точный маршрут не подсвечен;
- крупная фраза: **«Сначала найдём, как шум попадает в комнату.»**;
- подпись: `СИМПТОМ ≠ ИСТОЧНИК`;
- CTA присутствует, но визуально вторичен: «Записаться на диагностику».

Начальная сцена должна быть понятна без движения: интерьер + вторгающееся поле + основной тезис.

#### 24–49% — Состояние 2. Скан

- камера проходит на 3–4% ближе;
- поверхности становятся полупрозрачными по мере прохождения единственной измерительной плоскости;
- кратко загораются возможные маршруты: потолочное примыкание, боковая стена, вентиляционный канал, розетка, пол;
- mono-подписи показывают не «магические данные», а типы проверки: `ПРИМЫКАНИЕ`, `КАНАЛ`, `ПЕРЕКРЫТИЕ`;
- waveform меняет форму при прохождении разных узлов;
- headline сокращается до: **«Проверяем поверхности, каналы и примыкания.»**

Скан не повторяется после завершения. При обратном скролле корректно возвращается.

#### 49–74% — Состояние 3. Диагноз

- один доминирующий путь переходит из signal coral в acoustic teal;
- остальные пути теряют насыщенность и амплитуду, но не исчезают мгновенно;
- графическая камера разворачивает помещение в мягкий x-ray cutaway;
- крупный вывод: **«Не поверхность. Путь передачи.»**;
- рядом с маршрутом появляется последовательность `ИСТОЧНИК → ПРИМЫКАНИЕ → КОМНАТА`;
- короткий supporting copy: «Состав решения определяют после проверки маршрута, стадии ремонта и ограничений комнаты.»

#### 74–100% — Состояние 4. Решение

- релевантная поверхность отделяется в 3–4 конструктивных слоя;
- сборка показывает массу, развязку, герметизацию и примыкание без выдуманного названия системы;
- слои возвращаются на место, acoustic field уменьшается по амплитуде и плотности;
- комната снова становится непрозрачной и теплее;
- CTA выходит на первый план: **«Разобрать мой шум»**;
- microcopy: «Бесплатная первичная диагностика. Следующий коммерческий шаг — выездная диагностика.»

Финальный кадр не обещает абсолютную тишину: остаётся слабая измерительная линия, обозначающая контролируемый результат.

### 3.3. Управление и состояния

- ScrollTrigger pin — только внутри hero, ориентир 220vh, допустимый диапазон 180–260vh после тестов;
- scrub 0.2–0.45 s для сглаживания без отрыва от пользователя;
- anchor links переводят к логическим state boundaries, а не в произвольную середину;
- при resize таймлайн пересчитывается без скачка;
- при потере WebGL сцена остаётся как четыре подготовленных DOM/image состояния;
- CTA доступен с начала и не блокируется Canvas.

## 4. Noise profile selector — «Что именно вы слышите?»

Сцена выглядит как круговая/дуговая консоль вокруг фрагмента комнаты, а не как шесть равных карточек. На desktop выбор доступен мышью, клавиатурой и стрелками; на mobile — горизонтальный stepper с явным `1/6`.

| Профиль | Характер waveform | Вероятные пути в визуале | Смена сцены | CTA-контекст |
|---|---|---|---|---|
| Топот сверху, ~40% | резкие низкочастотные пики с паузами | перекрытие, примыкания стен, фланги | камера поднимает точку наблюдения к потолку | «Разобрать ударный шум сверху» |
| Голоса через стену, ~25% | плотная среднечастотная огибающая | стена, розетки, примыкания | боковая поверхность становится полупрозрачной | «Проверить путь голосов» |
| Бас и музыка, ~15% | длинная низкая волна | перекрытия и конструктивные связи | комната слегка пульсирует по глубине, не по масштабу UI | «Разобрать низкочастотный шум» |
| Лифт и вибрация, ~7% | редкие механические импульсы | шахта, плиты, жёсткие связи | появляется дальняя вертикальная ось здания | «Проверить структурную вибрацию» |
| Дорога и улица, ~7% | широкополосный непрерывный слой | окно, откосы, фасадные примыкания | точка наблюдения смещается к фасаду | «Разобрать уличный шум» |
| Вентиляция, ~6% | ровный шум с узкими пиками | канал, решётка, смежные помещения | активируется маршрут по воздуховоду | «Проверить вентиляционный путь» |

При выборе синхронно меняются минимум четыре слоя: waveform, путь, тональность/кадр комнаты, CTA. Выбранный профиль сохраняется до scenario lab и формы.

Переход между профилями — 420–600 ms: текущая энергия затухает, геометрия маршрута перестраивается, новая энергия входит от источника. Crossfade двух картинок без изменения модели недостаточен.

## 5. Apartment x-ray — карта маршрутов

### Начало

Узнаваемая акcонометрическая квартира показана как единый объём. Входящий импульс виден, но его путь неоднозначен.

### Середина

Пользователь выбирает один объект: стены, потолок, пол, розетки, вентиляцию или примыкания. Остальная архитектура уменьшается по контрасту. Энергия проходит по реальной связной траектории, может огибать очевидную поверхность.

### Финал

После исследования двух маршрутов сцена автоматически формулирует вывод: **«Слышно здесь — передаваться может через соседний узел.»** CTA получает выбранный путь.

Поведение:

- desktop: pointer/focus изолирует слой, click фиксирует выбор;
- mobile: кнопки объектов + пошаговый SVG/Canvas маршрут;
- путь рисуется один раз после выбора, затем остаётся статичным;
- `Esc` или повторный click снимает фиксацию;
- tooltip не содержит критически важного текста — вывод дублируется в постоянной панели.

## 6. Engineering assembly — конструкция как система

Один выбранный узел занимает почти весь viewport. Скролл 160–190vh разводит и возвращает слои:

1. исходная поверхность и отмеченный путь;
2. **масса** — тяжёлый слой входит медленно, без bounce;
3. **развязка** — между поверхностями появляется физический зазор;
4. **герметизация** — периметр замыкается непрерывной линией;
5. **примыкания** — камера приближает критический узел;
6. сборка возвращается, амплитуда пути уменьшается.

Лейблы появляются рядом с соответствующей геометрией и исчезают после сборки. Нельзя показывать конкретную толщину, материал, бренд или обещанный результат без исходных данных.

## 7. Renovation-stage morph — одна комната, три состояния

Одна и та же точка камеры проходит через три стадии без трёх карточек:

- **До ремонта:** открытые основания, максимум свободы трассировки, ранняя координация узлов;
- **Ремонт идёт:** частично собранные конструкции, решения нужно согласовать со смежными работами;
- **Квартира готова:** защищённый интерьер, локальные раскрытия, ограничения по демонтажу и потере пространства.

Между состояниями меняются не только изображения: появляются/исчезают доступные зоны обследования, масштаб вмешательства и список неизвестных. На mobile — snap-free sequence из трёх полноширинных кадров с фиксированным планом комнаты.

## 8. Case measurement stories

Три результата оформляются как три полноэкранные главы с разной композицией графика:

1. **58 dB → 39 dB** — линия до/после проходит через вертикальный разрез;
2. **пик 71 dB → снижение на 16 dB** — одиночный ударный пик сжимается, число результата формулируется именно как снижение;
3. **64 dB → 43 dB** — две измерительные огибающие расходятся и фиксируются как достигнутый результат.

Таймлайн каждой главы:

- 0–30%: noisy waveform и исходное число;
- 30–70%: изображение отходит на второй план, график объясняет изменение;
- 70–100%: итоговое число фиксируется, появляется честная подпись «Визуализация кейса; не документальная фотография объекта» и CTA `Открыть кейс`.

Числа интерполируются только между подтверждёнными значениями. Анимация не создаёт дополнительные показатели и не изображает лабораторный протокол, которого нет.

## 9. Preliminary scenario lab

Это не калькулятор цены. Интерфейс собирается вокруг одной схематической комнаты. Каждый ответ меняет карту зон, а не только текст справа.

Входы:

- основной шум;
- вероятное направление;
- стадия объекта;
- комната;
- проблемная зона;
- допустимая потеря пространства;
- комментарий.

Выходы:

- вероятный тип шума;
- зоны, которые следует проверить;
- ориентировочный масштаб вмешательства без площади и цены;
- что пока неизвестно;
- следующий диагностический шаг.

Переходы короткие и причинные: выбранная зона подсвечивается, неизвестные остаются пунктиром, подтверждённые пользователем данные становятся сплошной линией. CTA переносит контекст в форму.

## 10. Critical-node inspection

Вместо галереи карточек — крупный макроразрез узла. Четыре hotspot:

- периметр;
- крепёж;
- проходка;
- примыкание.

Hover/focus/тап раскрывает локальный x-ray и короткий критерий контроля: технология, фиксация скрытых работ, согласованный критерий приёмки. После открытия всех hotspot схема собирается в контрольный лист. Не показывать вымышленный гарантийный срок.

## 11. Diagnostic flow

Форма ощущается как финальная калибровка, но остаётся обычной доступной формой:

- прогресс — `СИМПТОМ → ОБЪЕКТ → МАТЕРИАЛЫ → КОНТАКТ`;
- выбранные ранее шум, путь и стадия уже заполнены и видимы;
- загрузка плана/фото/видео/аудио помещает файл в диагностическую рамку;
- запись с телефона подписана как контекст, не замена профессиональному замеру;
- success показывается только после подтверждения сервера;
- после success ясно: менеджер свяжется, следующий коммерческий шаг — выездная диагностика.

## 12. Micro-interactions

- кнопка на press сжимает внутренний signal field на 2–3 px, сама кнопка не прыгает;
- курсор-реактивное поле допустимо только внутри hero и выключается при coarse pointer;
- progress-nav меняет сегмент на границах смысловых глав;
- page transition между service routes использует один короткий переход `room → section → room`, максимум 700 ms и не задерживает навигацию;
- endless marquee, плавающие иконки и бесконечные scan-line запрещены.

## 13. Reduced motion

При `prefers-reduced-motion: reduce` смысл не исчезает:

| Сцена | Эквивалент |
|---|---|
| Hero | четыре статичных состояния с кнопками `Симптом / Скан / Путь / Решение`; sticky отключён |
| Noise selector | мгновенная смена изображения, SVG-пути и текста; waveform статичный |
| X-ray | выбранный объект получает контур; полный маршрут показывается сразу |
| Assembly | слои разнесены в статичной exploded-схеме, все четыре принципа доступны списком |
| Renovation stages | три последовательных кадра без морфа |
| Cases | исходное и итоговое значения видны одновременно; график статичен |
| Scenario lab | обычная пошаговая форма с обновляемой схемой без tween |
| Critical nodes | hotspot раскрывает статичную подпись |

Дополнительно:

- smooth scrolling выключен;
- автоигра и scrub-анимации выключены;
- opacity может меняться не дольше 100 ms только как системная обратная связь;
- контент не зависит от завершения animation event;
- focus не перемещается автоматически.

## 14. Производительность и отказоустойчивость

- первый экран получает оптимизированный poster до загрузки motion-модуля;
- WebGL/Canvas импортируются динамически после первого осмысленного рендера;
- один WebGL-контекст максимум; при переходе к другим сценам ресурсы освобождаются или переиспользуются;
- target — плавный scrub на обычном ноутбуке, без требования 60 fps на слабом mobile;
- при `save-data`, low memory или coarse pointer используется 2.5D/SVG fallback;
- изображения имеют фиксированные размеры и responsive variants;
- при hidden tab timeline ставится на паузу;
- Canvas не перехватывает pointer у CTA и навигации;
- все state boundaries тестируются на 0/25/50/75/100%, а также при обратном скролле.

## 15. Motion gate

Сцена проходит проверку, если:

1. понятны начальное, промежуточное и конечное состояния;
2. движение отвечает на инженерный вопрос;
3. тот же вывод доступен без анимации;
4. keyboard, touch и back-scroll не ломают состояние;
5. эффект не маскирует CTA и не снижает читаемость;
6. mobile сохраняет характер взаимодействия, а не показывает один статичный кадр.
