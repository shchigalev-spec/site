# SIGNAL / TECH — Final Interaction Notes

## Граница проверки

Проверены финальные статические captures, hero states `0–3`, reduced-motion capture и актуальный live build через Playwright. Live-проверка подтверждает состояние интерфейса и браузерное поведение; она не является лабораторным замером FPS, LCP или сетевой производительности.

В full-page captures после pinned hero и renovation видны большие тёмные footprints. Это ограничение способа съёмки sticky-секций: при обычном скролле соответствующая viewport-сцена остаётся pinned и последовательно меняет состояние.

## 1. Pinned hero — PASS

- Четыре состояния активируются и имеют самостоятельные заголовки и смысл: симптом, сканирование, маршрут диагноза, конструктивное решение.
- State `0–3` сохраняют визуальную continuity одной жилой сцены; clean anchor и cutaway больше не выглядят разными помещениями.
- Desktop scroll narrative и явные state controls дают пользователю и постановочное, и прямое управление.
- На mobile четыре кнопки имеют touch target `44px`; состояние `3` открывается без overflow.
- В reduced motion hero занимает один viewport, состояния остаются доступны вручную, контент не исчезает.

## 2. Noise deck — PASS

- Шесть источников шума меняют waveform, контекст, вероятные пути и диагностический вывод, то есть взаимодействие несёт новый смысл, а не только декоративный эффект.
- Поддержаны pointer/touch и клавиатурное управление стрелками.
- Активное состояние, числовые показатели и следующий CTA различимы на проверенных ширинах.

## 3. Apartment x-ray selector — PASS с revision note

- Выбор пути меняет активную трассу и объяснение акустического переноса.
- Маршруты читаются как диагностические гипотезы, а не как абстрактная glow-графика.
- Неблокирующее улучшение: вынести baked route/signal graphics из raster в code overlay; заменить бесконечный alternate pulse на однократный draw-and-hold.
- На mobile выбранный пункт может оказаться вне первого видимого участка горизонтального ряда, хотя результат выбора остаётся явно подписан в output.

## 4. Construction assembly — PASS

- Разбор узла связывает визуальный слой конструкции с конкретным объяснением и диапазоном результата.
- Интерактив поддерживает главный тезис: решение выбирается после определения пути передачи, а не по универсальному «пирогу».
- Семантический цвет и технические подписи остаются вторичны по отношению к жилой сцене.

## 5. Renovation stages — PASS после повторной проверки

- Scroll progress реально связан с `activeIndex`: проверены границы примерно `0 → new-build`, `.34 → renovation`, `.70 → finished`.
- Все три состояния используют согласованную комнату и камеру; меняется именно стадия работ.
- Tabs переводят к соответствующим scroll boundaries и дают прямой выбор.
- В reduced motion sticky поведение снято, frame становится обычным `position: relative`, все состояния доступны без обязательной анимации.
- На mobile используется понятный tabs/single-scene режим; это функционально, хотя менее кинематографично, чем последовательные full-width frames из art direction.

## 6. Measured cases — PASS с imagery note

- Три кейса дают измеримый контекст, исходную проблему, вмешательство и результат без ложной универсальности.
- Cases работают как evidence chapters и поддерживают conversion narrative.
- Часть изображений содержит baked signal graphics, поверх которых интерфейс добавляет собственную графику. Это даёт лёгкое удвоение и остаётся главным imagery revision, но не ломает чтение результата.

## 7. Scenario builder — PASS

- Выбор вводных меняет output и контекст, поэтому interaction является диагностической репетицией, а не калькулятором с ложной ценой.
- Результат формулирует вероятный путь проверки и корректный следующий шаг.
- Desktop presentation соответствует laboratory-console логике. На mobile stacked multi-field flow понятен, но one-question-at-a-time stepper сильнее соответствовал бы motion narrative.

## 8. Critical nodes и FAQ — PASS

- Critical nodes раскрывают конкретные точки риска; FAQ снимает ключевые возражения перед формой.
- Состояния доступны мышью, touch и Tab.
- Неблокирующее accessibility улучшение: для групп, визуально работающих как tabs, добавить полный WAI-ARIA tab pattern, roving tabindex и Arrow Left/Right.

## 9. Diagnostic form — PASS

- Полный набор диагностических полей, необязательные файлы и следующий коммерческий шаг сформулированы ясно.
- File validation и server error states предусмотрены; CTA не обещает фиксированную смету до диагностики.
- Неблокирующее улучшение: связать ошибки с конкретными inputs через `aria-invalid` и `aria-describedby`.

## 10. Header, navigation и focus — PASS

- Compact CTA «Диагностика» виден на mobile.
- При открытии меню focus переходит на первую ссылку, Tab удерживается внутри, `Escape` закрывает меню, focus возвращается на trigger.
- Scroll lock включается на время меню и корректно восстанавливается после закрытия.
- Статичный label/progress `АКУСТИЧЕСКАЯ ЛАБОРАТОРИЯ / 28%` выглядит как динамический статус, хотя не отражает текущую главу; это неблокирующая consistency revision.

## 11. Reduced motion и техническое поведение — PASS

- `prefers-reduced-motion` не скрывает смысловые состояния: hero доступен кнопками, renovation превращается в статичную управляемую сцену, smooth behavior отключён.
- На ширине `390px` подтверждён `scrollWidth = viewport width`, горизонтального overflow нет.
- Production image `currentSrc` выбирает WebP, включая `-960.webp` на mobile; PNG остаётся fallback.
- Финальный browser review: `consoleErrors = []`, overflow `0`, reduced-motion PASS.

## Итог

Все ключевые смысловые интеракции доступны и поддерживают сюжет «наблюдение → измерение → диагноз → конструкция → заявка». Текущие замечания относятся к polish, imagery discipline и глубине accessibility pattern; hard blocker не обнаружен.
