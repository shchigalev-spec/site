## Factual and release boundaries

All primary bitmap visual anchors are generated by Codex. Case-adjacent art is explicitly identified as a visualization, not documentary customer photography. The implementation must not invent prices, reviews, addresses, object specifications, durations, legal guarantees, certificates, or undocumented case facts.

This is a code release candidate. Production activation still requires owner-approved privacy/consent text, real public contacts, a real HTTPS CRM webhook/token, optional analytics identifiers, and infrastructure checks from `docs/A-MODUL-LAUNCH-CHECKLIST.md`. Without a CRM webhook the application returns a visible 503 and never reports fake success.

## Acceptance rule

The final gate uses three independent read-only directors: Visual + Motion; Conversion + Engineering/Factual; Accessibility + Performance. The fast-execution override permits `CONDITIONAL PASS` only when no P0/P1 issues remain. After a localized fix, only the materially changed director is reinvoked. The Builder does not approve its own work.

Current required reports: Conversion + Engineering/Factual R2 remains valid because its area was not changed; Accessibility + Performance R3 is accepted under the override with no P0/P1; Visual + Motion R3 blocked one localized final-state issue, so only a fresh Visual + Motion R4 review is required after the correction and fresh evidence.
