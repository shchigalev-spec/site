# Чек-лист запуска двух сайтов

Пустой чекбокс означает «не проверено». Отмечать пункт можно только после фактической проверки; наличие кода само по себе не является доказательством.

## 1. Факты и тексты

- [ ] Публичный бренд везде — «Лаборатория тишины», без добавления «Дом».
- [ ] Формулировка опыта не расширена дальше «15 лет работаем с шумом и вибрацией».
- [ ] Основная география обозначена как Москва.
- [ ] Бесплатной названа только подтверждённая первичная диагностика; условия выезда не выдуманы.
- [ ] Нет цен, стоимости за м², точного калькулятора или неподтверждённых диапазонов.
- [ ] Нет вымышленных адресов, ЖК, клиентов, отзывов, логотипов, рейтингов и сертификатов.
- [ ] Нет вымышленных сроков, бюджетов, систем, материалов и деталей протоколов кейсов.
- [ ] Гарантия описана только утверждёнными безопасными формулировками.
- [ ] 58 дБ → 39 дБ показано как достигнутый результат.
- [ ] Пиковый уровень 71 дБ описан как снижение на 16 дБ без придуманного конечного измерения.
- [ ] 64 дБ → 43 дБ показано как достигнутый, а не целевой результат.
- [ ] Иллюстрации кейсов не названы фотографиями реальных объектов.
- [ ] Доли сценариев подписаны как приблизительные данные компании, а не статистика рынка.
- [ ] В пользовательском интерфейсе нет TODO, lorem ipsum, тестовых контактов и технического текста.

## 2. Различие концепций

- [ ] Сайты не используют общий runtime UI-пакет.
- [ ] Нет общих компонентов, CSS, дизайн-токенов, шаблонов страниц и декоративных SVG.
- [ ] Основные изображения двух концепций не повторяются.
- [ ] Герои имеют разную геометрию и разный сценарий.
- [ ] Различаются порядок секций, навигация, формы, кейсы, мобильная композиция и язык движения.
- [ ] Сравнительная проверка подтвердила, что это не один сайт в двух темах.
- [ ] Шрифт Inter нигде не используется.

## 4. SEO

- [ ] На каждой индексируемой странице один H1 и осмысленная структура заголовков.
- [ ] `title` и `description` уникальны и соответствуют намерению маршрута.
- [ ] Canonical использует утверждённый production-домен.
- [ ] Open Graph-метаданные и локальные изображения работают.
- [ ] `sitemap.xml` содержит только доступные канонические страницы.
- [ ] `robots.txt` указывает правильный sitemap.
- [ ] 404 и служебные страницы имеют корректные правила индексации.
- [ ] Структурированные данные не содержат вымышленных адресов, рейтинга, цен и графика.
- [ ] Нет скрытого текста, переспама и городских дорвеев.
- [ ] Принято SEO-решение по одновременной публикации двух концепций.

## 5. Предварительный сценарий

- [ ] Результат меняется в зависимости от введённых данных.
- [ ] Результат ограничен вероятным типом шума, зонами проверки, масштабом вмешательства, неизвестными и следующим шагом.
- [ ] Нет точной цены, гарантированной системы или обещанного снижения дБ.
- [ ] Показано, что сценарий не заменяет обследование и не является сметой.
- [ ] Выбранный контекст передаётся в форму диагностики.

## 6. Форма и файлы

- [ ] Обе формы собирают общий согласованный набор полей.
- [ ] Имя, телефон и согласие валидируются; обязательность остальных полей соответствует спецификации.
- [ ] Email остаётся необязательным.
- [ ] План, фото, видео и аудио необязательны.
- [ ] Работают drag-and-drop и мобильный выбор файла.
- [ ] Проверены PDF, JPG, PNG, HEIC, MP4, MOV, M4A, MP3 и WAV.
- [ ] Утверждены и одинаково проверяются число, размер и общий вес файлов.
- [ ] Файл можно удалить; доступная ошибка видна и связана с полем.
- [ ] Есть понятное состояние обработки.
- [ ] Показана фраза: «Запись с телефона помогает понять контекст, но не заменяет профессиональный замер».
- [ ] Данные и файлы реально доходят до тестовой заявки Bitrix.
- [ ] Ошибка Bitrix не выдаётся за успех.
- [ ] Production-успех показывается только после серверного подтверждения.
- [ ] После принятия заявки объяснено: менеджер свяжется и обсудит выездную диагностику.
- [ ] В интерфейсе нет обещания неподтверждённого срока ответа.
- [ ] Политика конфиденциальности и согласие утверждены юристом.

## 7. Конфигурация и безопасность

- [ ] В обеих средах заданы `BITRIX_WEBHOOK_URL`, `BITRIX_ASSIGNED_BY_ID`, `BITRIX_SOURCE_ID`.
- [ ] В обеих средах заданы `PUBLIC_YANDEX_METRICA_ID`, `PUBLIC_SITE_PHONE`, `PUBLIC_SITE_EMAIL`.
- [ ] Секреты не попали в клиентский bundle, репозиторий, логи и скриншоты.
- [ ] Телефон и email в интерфейсе совпадают с утверждёнными значениями.
- [ ] Сервер повторно проверяет поля, MIME/расширение, размер и число файлов.
- [ ] Ошибки и журналы не содержат PII и содержимого вложений.
- [ ] Определены хранение, доступ и удаление загруженных файлов.
- [ ] Проверены защита от повторной отправки и безопасное поведение при таймауте.

## 8. Аналитика

- [ ] Счётчик загружается только с реальным ID и по принятому режиму согласия.
- [ ] Все события из `docs/06-ANALYTICS-SPEC.md` проверены в Tech и Engineering.
- [ ] Каждое событие содержит правильное `concept`.
- [ ] Нет двойных `page_view`, `service_page_view`, `scroll_50` и `scroll_90`.
- [ ] `form_started` не срабатывает от автофокуса.
- [ ] `file_attached` не срабатывает для отклонённого файла.
- [ ] `form_submit_success` отправляется только после принятия сервером.
- [ ] В payload нет имён, телефонов, email, комментариев, имён файлов и иных PII.
- [ ] Блокировка Метрики не ломает сайт и форму.
