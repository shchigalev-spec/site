# Спецификация аналитики

## Назначение

Обе концепции используют одинаковые названия событий и различаются обязательным свойством `concept`:

```text
concept = tech | engineering
```

Целевая система — Яндекс Метрика. Идентификатор счётчика передаётся через `PUBLIC_YANDEX_METRICA_ID`; вымышленное значение в коде и документации не используется.

Аналитика не должна блокировать основной сценарий. Если счётчик не настроен или недоступен, интерфейс и отправка заявки продолжают работать.

## Общий контракт события

Минимальная структура:

```ts
type AnalyticsEvent = {
  name: EventName;
  concept: 'tech' | 'engineering';
  path: string;
  page_type: 'home' | 'service' | 'diagnostic' | 'cases' | 'case' | 'legal' | 'not_found';
  timestamp?: string;
  context?: Record<string, string | number | boolean | null>;
};
```

`timestamp` нужен только внутренней очереди, если она реализована. В Метрику не передаются имя, телефон, email, комментарий, содержимое файла, имя файла, полный URL с персональными query-параметрами или свободный пользовательский текст.

## События

| Событие | Когда отправлять | Рекомендуемый контекст | Защита от дублей |
|---|---|---|---|
| `page_view` | После подтверждённого открытия или клиентского перехода на страницу | `title`, `referrer_type` при безопасной классификации | Один раз на просмотр маршрута |
| `hero_cta_click` | Клик по главному CTA первого экрана | `cta_variant`, `destination` | На каждый осознанный клик |
| `diagnostic_start` | Пользователь открыл первый шаг диагностики | `entry_point` | Один раз за запуск сценария |
| `noise_selected` | Выбран тип шума | `noise_type`, `entry_point` | При фактической смене значения |
| `path_selected` | Выбран предполагаемый путь или направление | `path_type` | При фактической смене значения |
| `renovation_stage_selected` | Выбран этап объекта | `stage` | При фактической смене значения |
| `scenario_started` | Пользователь начал предварительный сценарий | `entry_point` | Один раз за экземпляр сценария |
| `scenario_completed` | Получен изменяемый предварительный результат | `noise_type`, `stage`, `room_type`, `intervention_scale` | Один раз для завершённой версии ответов |
| `form_started` | Первое содержательное взаимодействие с формой | `form_id`, `entry_point` | Один раз за экземпляр формы |
| `file_attached` | Файл прошёл клиентскую проверку и добавлен | `file_category`, `extension`, `size_bucket` | По одному событию на принятый файл |
| `form_validation_error` | Отправка или переход шага остановлены валидатором | `form_id`, `field_id`, `error_code`, `step` | Одно событие на попытку, не на каждый ререндер |
| `form_submit_success` | Сервер подтвердил принятие заявки | `form_id`, `lead_reference_present` без самого идентификатора | Строго один раз на принятую заявку |
| `form_submit_error` | Сервер вернул ошибку или запрос завершился техническим сбоем | `form_id`, `error_category`, `http_status` | Один раз на неуспешную попытку |
| `phone_click` | Клик по ссылке `tel:` | `placement` | На каждый клик |
| `email_click` | Клик по ссылке `mailto:` | `placement` | На каждый клик |
| `faq_open` | Пользователь раскрыл ответ | `faq_id`, `page_type` | При переходе из закрытого состояния в открытое |
| `scroll_50` | Впервые достигнуто 50% доступной глубины страницы | `page_type` | Один раз на просмотр маршрута |
| `scroll_90` | Впервые достигнуто 90% доступной глубины страницы | `page_type` | Один раз на просмотр маршрута |
| `case_open` | Открыт кейс из списка, навигации или интерактивной главы | `case_id`, `source` | На каждый переход к кейсу |
| `service_page_view` | Открыта одна из коммерческих service-страниц | `service_type` | Один раз на просмотр service-маршрута |

## Справочники параметров

Использовать стабильные машинные значения, а не видимый текст:

- `noise_type`: `impact_top`, `voices_wall`, `bass_music`, `elevator_vibration`, `street`, `ventilation`, `unknown`;
- `stage`: `new_build`, `renovation`, `finished`, `unknown`;
- `room_type`: `bedroom`, `living_room`, `nursery`, `kitchen`, `office`, `multiple`, `other`;
- `case_id`: `58_39_db`, `impact_minus_16_db`, `64_43_db`;
- `service_type`: `apartment`, `walls`, `ceiling`, `floor`, `neighbors`, `new_build`, `finished_apartment`, `noise_diagnostics`;
- `file_category`: `plan`, `photo`, `video`, `audio`, `document`;
- `size_bucket`: например `lt_5mb`, `5_20mb`, `gt_20mb`; реальные лимиты определяются после технического решения;
- `placement`: стабильный код места, например `header`, `footer`, `diagnostic`, `final_cta`.

Категории не должны кодировать персональные сведения.

## Яндекс Метрика

После загрузки счётчика событие может передаваться через единый адаптер как достижение цели с параметрами. Точное соответствие целей и настройки счётчика подтверждаются владельцем аналитики до запуска.

Требования к адаптеру:

- не обращаться к `ym`, пока функция не доступна;
- безопасно переживать блокировщики и отсутствие ID;
- не включать фиктивный ID;
- централизованно добавлять `concept`, `path` и `page_type`;
- одинаково обрабатывать обычную загрузку и клиентскую навигацию;
- исключать дубли при гидратации;
- в разработке предоставлять диагностический лог без персональных данных;
- не считать серверную ошибку успехом.

## Воронки

Основная воронка:

```text
page_view
→ hero_cta_click или diagnostic_start
→ form_started
→ form_submit_success
```

Воронка предварительного сценария:

```text
scenario_started
→ noise_selected / path_selected / renovation_stage_selected
→ scenario_completed
→ diagnostic_start
→ form_started
→ form_submit_success
```

Исследовательская воронка:

```text
service_page_view или case_open
→ diagnostic_start
→ form_started
→ form_submit_success
```

Сравнение Tech и Engineering строится по свойству `concept`, а не через разные названия целей.

## Проверка перед запуском

- ID счётчика поступает из production-окружения.
- События не отправляются до выполнения принятого для проекта режима согласия; юридическое решение зафиксировано.
- На одном просмотре нет двойных `page_view`, `service_page_view`, `scroll_50` и `scroll_90`.
- Клавиатурная и pointer-активация одного элемента дают одно событие.
- `form_started` не срабатывает от автофокуса.
- Ошибка клиентской валидации не отправляет `form_submit_error`.
- `form_submit_success` срабатывает только после серверного подтверждения.
- Отклонённый по формату или размеру файл не считается `file_attached`.
- Ни один payload не содержит PII или свободный текст.
- Переходы без JavaScript остаются рабочими, даже если событие не записано.
- События проверены отдельно для `tech` и `engineering`.
