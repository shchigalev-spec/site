# A-Modul Direct V2

Independent SvelteKit landing application for contextual-advertising traffic. It does not import runtime UI, CSS, components, assets, or tokens from the Silent Lab products.

## Routes

- `/modulnye-zdaniya/`
- `/vahtovye-poselki/`
- `/modulnye-ofisy-abk/`
- `/modulnye-obshchezhitiya/`
- `/privacy-policy/`
- `/sitemap.xml`
- `/robots.txt`
- `/api/leads` (`POST multipart/form-data`)

The root route redirects to `/modulnye-zdaniya/` while preserving allowlisted search intent and attribution parameters. Query variants are canonicalized to their primary route and use `noindex,follow`.

## Local development

From the repository root:

```bash
npm install
npm --prefix apps/a-modul run dev -- --host 127.0.0.1 --port 5175 --strictPort
npm --prefix apps/a-modul run check
npm --prefix apps/a-modul run lint
npm --prefix apps/a-modul run test
npm --prefix apps/a-modul run build
```

## Standalone HTML

Run `npm run build:a-modul:standalone` from the repository root. The generated `apps/a-modul/standalone/a-modul-direct.html` is a single self-contained copy of the general local route, built from the same Svelte components and CSS with inline JavaScript, fonts, and Codex-generated artwork. It opens directly from the filesystem without a local server or internet connection.

The standalone lead form is intentionally an offline demonstration: it validates locally and never reports a CRM success or transmits entered data.

Use `A_MODUL_CRM_MODE=mock` only with the development server for deterministic local success/error testing. Production builds reject mock success.

## Production adapter-node

Copy `.env.example` into the deployment secret/configuration system. Required boundaries:

- exact public `ORIGIN`, or trusted proxy `PROTOCOL_HEADER` / `HOST_HEADER` configuration;
- `BODY_SIZE_LIMIT=45M` or an equivalent upstream limit, set above the documented 40 MiB attachment total plus multipart overhead;
- HTTPS `A_MODUL_LEAD_WEBHOOK_URL` and optional bearer token;
- final public origin, contacts, Metrica ID, call-tracking URL, and approved legal policy.

Run the generated Node server from `apps/a-modul/build`. A browser-visible success appears only after the configured CRM webhook accepts the lead with a 2xx response.

## Assets and facts

All primary raster visuals were generated by Codex, optimized to responsive AVIF/WebP derivatives, and are labelled as visualizations where case facts are shown. Production assets live in `static/generated`; generation masters and exact prompts live under `docs/`. No video, external stock imagery, generated customer logo, invented price, or invented project fact is used.

Source, analytics, CRM, design, motion, and launch contracts are documented in `docs/A-MODUL-*.md`.

## Production-readiness boundary

The codebase is a release candidate, not a claim that external launch dependencies are complete. Real lead acceptance remains blocked until the owner supplies and verifies the production domain, approved legal policy, CRM endpoint, Metrica ID, call tracking, final contacts, and owner-approved claims.
